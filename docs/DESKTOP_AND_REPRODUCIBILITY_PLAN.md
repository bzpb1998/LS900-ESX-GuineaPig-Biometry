# 桌面版、界面与科研复现改进方案

日期：2026-10-29。本文保留方案依据。依用户随后授权，原生 Qt 窗口、新图标、共享 V5 API/CLI、Conda 环境描述和固定 Windows 依赖已实现；实际运行与发布状态以 Release 和复现说明为准。Conda 描述尚未在本机执行求解验证，不把它称为已验证的 Conda 锁文件。

## 1. 目标与现状

使用者需要下载一次、完整解压、双击 EXE 后直接出现独立软件窗口，不自动跳到 Edge/Chrome，不需要自己安装 Python、Conda 或配置端口。代码使用者另有可审查、可重复运行的分析入口。

现有 Windows v0.1.0 是 Python/PyInstaller 便携包，但启动器通过本机服务和外部浏览器显示界面。它不是新的独立窗口版本。现有 requirements.txt 规定依赖版本范围，不能当作完整的精确版本锁定文件；仓库尚无正式 Conda environment.yml。公开 Windows 包仍内置 V4，不能把本地 V5 实验结果当作现有 EXE 的表现。

## 2. 一个分析核心、两种入口

| 使用者 | 入口 | 要求 |
| --- | --- | --- |
| 懂代码、需要审查与批处理 | Python 包、命令行、专用 Conda 环境 | 可检查算法、固定模型、自动验证结果 |
| 不配置环境的使用者 | Windows 便携桌面版 | 双击打开窗口、导入 ESX、保存 Excel |

两种入口必须调用同一个 ESX 读取、推断、质量门控和 Excel 导出核心。不能为 GUI 再维护一套公式，也不必仅为正规化而把已有 Python 算法重写成 R 包。R 用户可读取输出 Excel；将来确有需求再提供调用封装。

## 3. 独立桌面窗口方案

建议优先使用 PySide6/Qt 原生窗口，分析在后台工作线程执行，窗口只负责文件选择、任务状态和导出。这样不需要外部浏览器，也不需要为界面启动本地 HTTP 服务；打包时携带 Python 与 Qt 依赖。目标发布形式为完整目录的 ZIP，不承诺只有一个 EXE，也不承诺与 Magpie 相同的体积。

另一种可选实现是内嵌 WebView，复用 HTML/CSS。Magpie（yetone/magpie）的官方文档说明其通过 Wails 使用系统 WebView，在 Windows 使用 WebView2。这解释了“网页技术但显示为软件窗口”的体验，不等于完全没有浏览器运行时依赖。若走此路线，必须验证目标 Windows 的 WebView2，或合规捆绑离线运行时，不能将联网补装依赖描述为严格离线免安装。

无论选哪种界面，不能改变锁定模型来让界面看起来更成功；V4 与 V5 分别命名和回归验证。关闭主窗口默认结束分析程序，而不是留下用户不知道如何退出的后台服务。

## 4. 界面与品牌

- 新 Logo 采用原创、简洁的眼部轮廓与轴向测量线或信号峰意象，统一深蓝/青绿配色，先检查小尺寸辨识度；矢量源文件和 Windows 多尺寸 ICO 一并保存。不使用厂家标志或暗示厂家认可的图案。
- 首页保留三个核心操作：添加/拖入 ESX、开始分析、保存 Excel。显示待处理文件数、进度、成功/失败数；失败文件可单独查看原因。
- 单独提供“使用说明”和“关于与引用”：支持的物种/文件、指标及单位、AL 边界定义、不可测如何处理、算法限制、软件和模型版本、源代码入口、许可证及引用方式。
- 样式目标是简洁专业的研究软件，不写“厂商官方”“临床认证”或没有依据的准确率。软件独立于 LENSTAR/Haag-Streit，仅供研究。
- 不设置 before/after 分类入口，不自动做动物组间或增长统计。
- Excel 继续一只动物一行，OD/OS 横向排列、中间两列留空，仅“测量数据”和“说明”两张表；不可用值不强行补造，需复核原因进入说明。技术审计记录不挤进测量主表。

## 5. 科研复现需交付什么

1. Python 包元数据与正式命令行入口；分析依赖与可选 GUI/打包依赖分开。
2. environment.yml 用于创建专用 Conda 环境，并另提供在实际验证平台生成的精确依赖锁定文件。不同操作系统分别验证，不能声称一份平台特定锁文件适用所有系统。
3. 明确区分用已发布模型进行推断与重新训练；记录软件版本、模型版本、模型 SHA-256、支持的 Python/系统和运行步骤。存在随机过程时保存种子。
4. 合成示例与预期输出用于检查安装和解析流程；合成例不能代替真实生物学准确性验证。真实示例需独立获准、脱敏后才能公开。
5. 自动测试与同输入回归检查：命令行、源码 GUI、打包 EXE 的数值在明确容差内一致；另外检查单位、左右眼、缺眼、坏文件、缺失晶体、中文路径及批量任务。
6. 在无 Python/Conda 的干净 Windows 环境验证启动、离线分析、Excel 打开和正常退出，再发布带校验和的 Release。
7. 完整训练复现还需要相应训练数据与参考标签。只公开代码和模型参数可以支持推断复现，但不能声称外部研究者已能完全复现训练。原始 ESX、人工参考、截图及患者/厂家资料不随代码上传；论文写明数据可用性边界。

专用环境是实现复现的一个条件，不是复现已被证明的充分条件。必须在新环境实际运行测试并留下版本记录。

## 6. 实施与验收顺序

1. 固定待发布的模型版本，保留旧版，不因界面更新切换模型或改动测试划分。
2. 规范 Python 包、命令行、环境文件和版本记录，跑通核心测试。
3. 制作新图标与独立桌面窗口，补充使用说明和研究边界。
4. 在本地私有数据上做三个入口的一致性检查；验证结果留在研究目录，不把原始数据塞进软件包。
5. 在干净 Windows 上测试便携包，审核第三方许可、公开树和敏感信息，再发布新 Release。GUI 依赖包含的 LGPL 等义务需单独落实，不能只保留项目 MIT 而忽略第三方许可证。
